# Little Cheers

A celebration homepage with a GSAP ScrollTrigger gallery, occasion and recipient filters, and a local template editor.

The gallery pins at the top of the viewport for a scroll-controlled sequence. Alternating columns travel upward and downward with staggered timing; the next section resumes after the sequence ends. Scrolling backward reverses the sequence. Filtering, expanding the gallery, or enabling reduced motion removes the pin. Travel distances are recalculated when ScrollTrigger refreshes after resizing or font loading.

Cards sit at different perspective depths and change depth and tilt throughout the scroll sequence. Mouse movement adds a gently eased parallax offset and surface lighting, with stronger movement on foreground cards. Touch devices retain the scroll-driven effect. Reduced motion disables both effects.

From the parent project, run `npm run dev` and open http://localhost:5173. Run `npm run build` to produce `site/dist`.

The editor supports text, colors, local photo uploads, browser-local draft saving, and downloadable HTML keepsakes. Uploaded photos are resized in the browser and embedded in exports. Sample photos use Unsplash URLs; fonts use Google Fonts with local fallbacks.

## Headliner concert birthday

Open `/concert.html`, or choose Headliner in the homepage gallery. All gallery templates now open in a new tab; the other templates have a full-page preview at `/template.html?id=...`.

Headliner uses the supplied concert flight video. Enter concert switches to a viewport-filling arena and starts at scroll zero. A native page scroll range drives the 10-second flight from the crowd to the stage, then holds the final frame for the memories and dedication. The arena stays fixed while mouse-wheel, touch, and keyboard scrolling move the playhead; this page does not depend on GSAP or ScrollTrigger. Video seeks can begin as soon as metadata is ready, and pending seeks catch up to the latest scroll position. Branding and editorial overlays disappear. Move the pointer, tap, or use Tab to reveal Edit screens, Audience notes, Birthday message, Replay, and Exit; Escape exits the concert when the editor is closed.

The video supplies the camera movement, flames, lighting, and crowd. Three LED screens and two audience cards use per-frame corner tracks from `concert-tracking.js`, mapped with projective transforms. Cards disappear as the camera passes them. A symmetric five-frame filter reduces edge-detection noise without delaying the track. Surfaces keep a fixed layout size; only their transform changes on displayed frames. The video frame is copied to a presentation canvas alongside the matching overlays, avoiding independent video/overlay paint timing. The previous CPU pixel-readback haze mask has been removed; confetti is no longer composited over replacement screen content. `scripts/track-concert.py` regenerates the original edge tracks from the extracted analysis frames in `output/concert-frames`.

Playback uses `concert-scrub.mp4`: 1280 × 720, 24 fps, all 241 frames independently decodable, with the MP4 index at the beginning. It is 31,266,812 bytes versus the original 15,428,970 bytes; the larger playback file preserves source resolution with high-quality, independently decodable frames (CRF 18). The opening poster and final still are also 1920 ? 1080. Recreate it with `powershell -File scripts/prepare-concert-video.ps1` (FFmpeg required). The original 1920 × 1080 video remains available for offline tracking. Seeking keeps only the latest requested position and waits for the displayed frame before issuing another seek. Browsers with `requestVideoFrameCallback` use its media timestamp; older browsers fall back to `seeked`. No pixel readback or per-frame layout measurement runs during the flight. See [the frame callback documentation](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback) and [FFmpeg encoding options](https://www.ffmpeg.org/ffmpeg-all.html).

Choose **Align screens** in the concert controls (or **Align screens & audience cards** in the editor). Select the surface whose text/photos you want to attach, then drag the four numbered anchors onto its inner corners. Drag the center handle to move all corners together. Use the timeline or frame arrows to inspect later frames and add corrections where the track drifts. Dragging or keyboard nudging creates an anchor keyframe; **Apply tracking** saves it with the browser draft and includes it in downloads. Closing without applying discards the alignment edits. Corrections interpolate over the existing motion between keyed frames, holding the nearest correction outside them; they do not perform optical flow in the browser. A single point controls position, while four corners also control scale, rotation, and perspective.

The main screen now uses the user's 23 anchors in `scripts/tracking/main-screen-anchors.json` (frames 0–72), extended through frame 240 by the offline OpenCV tracker. Its `surfaceMethods` entry bypasses the browser smoothing pass so supplied pins remain exact. Existing drafts containing these same anchors do not apply the correction twice. The other four surfaces retain their original tracks. The sampled review is `output/concert-main-anchor-review.jpg`; the full tracking report is `output/concert-main-candidate.report.json`. Frames after 3 seconds are optical-flow estimates rather than additional user-pinned positions.

**Export anchors** downloads JSON for the optional OpenCV offline tracker. Install with `py -3.12 -m pip install -r scripts/tracking-requirements.txt`, then run `py -3.12 scripts/track-concert-opencv.py --anchors path/to/concert-anchors.json`. It uses [Lucas-Kanade optical flow](https://docs.opencv.org/doc/doxygen/html/dc/d6b/group__video__track.html), forward/backward feature validation, and RANSAC homographies seeded by the user's anchors. Bidirectional tracks are blended between anchor frames. Occlusions fall back to the baseline and are flagged in the report. Review `output/concert-opencv-tracking.js` and its report before replacing the site's track. OpenCV 4.14.0 and NumPy 2.5.4 are installed in Python 3.12; use `py -3.12` because the default `python` command selects Python 3.9. The working browser editor and player do not require that package.

Uploaded photos, individual photo captions, the screen headline, names, ages, crowd placards, messages, and sender names are editable. Photo framing can preserve the full image or fill the screen. Photos progress with scroll and can also be changed with previous/next controls. Birthday message opens the dedication; Back to memories returns to the photos. Local drafts use a separate key for the concert. Downloaded HTML embeds the player, video, tracking data, posters, and uploaded photos; sample photos and Google Fonts require internet. The recipient copy hides editing controls and disables card editing. Reduced-motion users get the final video frame with photo navigation and the birthday-message control, without a scroll journey.

With `npm run dev` running, run `npm run check:concert` to check all 9,420 original screen/card projection corners, 3,140 fixed-plane corners, editor bindings, video byte-range serving, and source/build consistency. It also exercises the download handler, compiles exported scripts, and verifies that special characters and tracking anchors survive and the video is embedded only once. Controller checks cover native scrolling, exact anchors, correction interpolation, invalid-anchor rejection, coalesced seeking, duplicate-frame suppression, and both frame-callback and fallback modes. Run `npm run build` before these checks after editing source files. The math benchmark measures all five surfaces, excluding browser decoding and painting (approximately 0.012–0.017 ms per frame in this environment).

`npm run check:concert:browser` checks mouse-wheel/keyboard seeking, anchor editing and persistence, card visibility, editing, saved drafts, exit/reentry, mobile sizing, reduced motion, and an offline downloaded celebration in Playwright using installed Microsoft Edge. Set `CONCERT_PLAYWRIGHT_PATH` to the available Playwright package if it is not installed locally. Browser launch is currently blocked in the coding sandbox (`spawn EPERM`), so this check must be run in an environment that permits browser processes. Browser checks save screenshots, a downloaded sample, and `concert-performance.json` in `output/`. `window.concertPerformance()` exposes frame counts, render duration, and seek-to-frame latency for profiling on the actual device. End-to-end visual smoothness has not been verified in this environment.

`scripts/prepare-concert.cjs` prepares web assets from the user's original files using Sharp (a development tool, not a runtime dependency). Original files in Downloads are never modified. The generated `placements.json` records estimated crop positions in the 3840 × 2160 master. The small runway cutout is retained as an asset but not displayed because the original crowd strip already contains that detail at a more appropriate scale.

This version does not provide accounts, a database, or hosted links for individual celebrations. Drafts are specific to the browser and device. Publishing that platform functionality requires a backend.

GSAP and ScrollTrigger are copied from the installed parent dependencies during the build. React and Motion are installed for subsequent application work; this homepage uses vanilla JavaScript and GSAP.
